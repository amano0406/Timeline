# Timeline 設定画面改善計画

## 目的

この資料は、Timeline の設定画面を「ユーザーが迷わず設定できる画面」に整理するための改善計画です。

## 実装進捗

- [x] ~~「通常モード / プロモード」を「基本設定 / 詳細カスタマイズ」に変更する~~
- [x] ~~設定画面全体の保存導線を `保存` ではなく `確認` → `適用する` に寄せる~~
- [x] ~~詳細カスタマイズ内に各製品の既存設定ページを埋め込まず、製品ごとの保存ボタンを出さない~~
- [x] ~~未保存状態で画面遷移しようとしたら警告する~~
- [x] ~~Hugging Face トークンの個別設定状態を基本設定側に簡潔に表示する~~
- [x] ~~AI 処理方法の個別設定状態を基本設定側に簡潔に表示する~~
- [x] ~~基本設定と詳細カスタマイズの一時状態を、明示的な設定ドラフトとして管理する~~
- [x] ~~`この設定をすべての製品に適用する` を共通操作として実装する~~
- [x] ~~基本設定の AI 処理方法を変更しても、個別設定を明示操作なしに上書きしない~~
- [x] ~~適用前に、読み込み場所と生成データ保存先の未設定を止める~~
- [x] ~~トークンとディレクトリの即時検証を追加する~~
- [x] ~~適用時に、再起動が必要な製品と進行状況を表示する~~
- [x] ~~インストール時に Timeline 側の基本設定からサブ製品設定を作る~~
- [ ] サブ製品の `timeline-product.json` を使い、設定可能項目を推測せずに表示する

現在の設定画面には、以下の問題があります。

- 通常モード / プロモードという言葉の意味が分かりにくい
- 共通設定と製品ごとの設定の関係が分かりにくい
- Hugging Face トークンや AI 処理方法の設定が、どの製品に反映されるのか分かりにくい
- 製品ごとの設定に保存ボタンが分散している
- 保存前の変更が、別の表示モードに切り替えたときに維持されない
- 保存したときに、何が変わるのか、どの製品の再起動が必要なのかが分かりにくい
- インストール直後にサブ製品の `settings.example.json` が見えてしまい、Timeline 側で決めた保存先とずれる

改善後は、設定画面を以下の考え方に寄せます。

```text
基本設定
  Timeline 全体の標準設定を決める

詳細カスタマイズ
  製品ごとに標準設定と違う部分だけを上書きする

確認
  変更内容、影響範囲、再起動の必要性を確認する

適用
  設定を書き込み、必要な製品を再起動し、完了まで見届ける
```

## 画面名

従来の名前は、ユーザーに役割が伝わりにくいため変更します。

| 旧名称 | 新名称 | 意味 |
|---|---|---|
| 通常モード | 基本設定 | Timeline 全体の標準設定 |
| プロモード | 詳細カスタマイズ | 製品ごとの差分設定 |

## 基本設定

基本設定は、最初に見る画面です。

ここでは、できるだけ少ない項目だけを表示します。

主な項目:

- データ保存先
- 表示言語
- タイムゾーン
- Hugging Face トークン
- AI 処理方法
- 入力データの場所

### データ保存先

表示名:

```text
データ保存先
```

意味:

Timeline が作業データ、時間軸データ、各製品の生成データを管理する場所です。

初期値は Timeline 本体の製品ディレクトリ直下に作る `data` ディレクトリです。

例:

```text
C:\apps\Timeline\data
```

### 入力データの場所

従来の「入力ディレクトリ」よりも、ユーザーには次の表現を優先します。

```text
読み込み場所
```

音声、画像、動画など、素材種別ごとに複数登録できるようにします。

ボタン文言:

```text
追加
```

「音声を追加」「画像を追加」のように、ボタン側に種別名を重複させません。

### 生成データの保存先

従来の「出力ディレクトリ」よりも、ユーザーには次の表現を優先します。

```text
生成データの保存先
```

通常は Timeline が自動で管理します。

ユーザーが通常操作で細かく指定する必要はありません。

## Hugging Face トークン

基本設定では、Timeline 全体で使う標準トークンを設定します。

ただし、製品ごとに別のトークンを使う可能性があります。

そのため、基本設定のトークンは「全製品に必ず強制される値」ではなく、「標準値」として扱います。

### 表示パターン

#### すべての製品が基本設定を使っている場合

表示例:

```text
設定済み
hf_i••••••••••••••••••••••TnyF
```

操作:

```text
登録
```

#### 一部の製品が個別設定を使っている場合

表示例:

```text
一部の製品で個別設定があります
```

補足表示:

```text
TimelineForAudio、TimelineForVideo は個別のトークンを使用しています。
```

操作:

```text
確認
```

一括反映の操作:

```text
この設定をすべての製品に適用する
```

この文言は、Hugging Face トークン専用ではなく、AI 処理方法などにも使える汎用表現として採用します。

## AI 処理方法

AI 処理方法も Hugging Face トークンと同じ考え方で扱います。

基本設定では、標準の処理方法を選びます。

例:

```text
自動: GPU を使用
GPU
CPU
```

一部の製品だけ別の処理方法を使う場合は、基本設定側では以下のように表示します。

```text
一部の製品で個別設定があります
```

一括反映の操作:

```text
この設定をすべての製品に適用する
```

## 一括反映の文言

「すべて同じトークンを使う」は、トークン専用の表現になってしまいます。

今後、AI 処理方法、保存先、その他の共通設定でも同じ操作を使うため、より汎用的な文言にします。

推奨文言:

```text
この設定をすべての製品に適用する
```

短いボタンにする場合:

```text
全製品に適用
```

確認画面の見出し:

```text
この設定をすべての製品に適用しますか？
```

確認画面の説明:

```text
個別に設定されている製品も、この設定に揃えます。
```

破壊的ではないが注意が必要な操作として扱います。

理由:

- トークン以外にも使える
- CPU / GPU の設定にも使える
- 「統一」という言葉より分かりやすい
- 何をするボタンなのか予測しやすい

避ける文言:

```text
すべて同じトークンを使う
```

理由:

- Hugging Face トークン専用に見える
- AI 処理方法などに流用できない
- 製品ごとの差分を上書きする操作だと伝わりにくい

## 詳細カスタマイズ

詳細カスタマイズでは、インストール済みの製品だけを表示します。

未インストール製品の設定は表示しません。

理由:

- 設定を書き込む対象が存在しない
- ユーザーが「使える製品」と誤認する
- 設定しても実際には反映されない可能性がある

### 製品ごとの表示

各製品では、以下を設定できるようにします。

- Hugging Face トークン
- AI 処理方法
- 読み込み場所
- 生成データの保存先

ただし、製品ごとの設定に個別の保存ボタンは置きません。

保存操作は、設定画面全体で 1 箇所にまとめます。

### 基本設定を使う

製品ごとの設定には、基本設定を使う操作を用意します。

文言:

```text
基本設定を使う
```

意味:

その製品だけ、個別設定を解除して基本設定に戻します。

## 保存フロー

設定画面では、すぐに保存しません。

まず変更内容を確認し、その後に適用します。

ボタン:

```text
確認
```

確認後のボタン:

```text
適用する
```

「保存」だけでは、設定ファイルを書くだけなのか、製品の再起動まで行うのかが分かりにくいため、最終実行ボタンは「適用する」を使います。

## 確認画面

確認画面では、ユーザーが判断できる情報だけを表示します。

表示するもの:

- 変更される項目
- 変更前の値
- 変更後の値
- 影響を受ける製品
- 再起動が必要な製品
- 検証エラー

表示例:

```text
変更内容

Hugging Face トークン
  基本設定を更新します。
  TimelineForAudio、TimelineForVideo にも適用されます。

AI 処理方法
  GPU に変更します。
  TimelineForAudio、TimelineForImage、TimelineForVideo の再起動が必要です。
```

## 適用中の表示

適用中は、ユーザーが待てるように進行状況を表示します。

表示例:

```text
設定を適用しています

1 / 4  設定を書き込み中
2 / 4  TimelineForAudio を停止中
3 / 4  TimelineForAudio を起動中
4 / 4  起動確認中
```

適用が完了したら、完了表示を出します。

```text
設定を適用しました
```

## 未保存状態

設定画面で値を変更したまま別画面へ移動しようとした場合は、警告します。

表示例:

```text
変更がまだ適用されていません。
このまま移動すると、変更内容は失われます。
```

操作:

```text
移動する
設定に戻る
```

## 入力値の検証

以下は、入力または選択した時点で検証します。

- Hugging Face トークン
- 読み込み場所
- 生成データの保存先

保存ボタンを押すまでエラーに気づけない状態は避けます。

## インストール時の初期設定

サブ製品をインストールした直後は、Timeline 側が初期設定を行います。

サブ製品の `settings.example.json` を実行時設定としてそのまま使いません。

優先順位:

1. 退避済みの設定がある場合は、それを使う
2. 退避済みの設定がない場合は、Timeline の基本設定から作る
3. `settings.example.json` は実行時設定として扱わない

初期値の考え方:

| 種別 | 初期値 |
|---|---|
| AI 処理方法 | GPU |
| 音声の読み込み場所 | `<data>\input\audio` |
| 動画の読み込み場所 | `<data>\input\video` |
| 画像の読み込み場所 | `<data>\input\image` |
| 音声の生成データ保存先 | `<data>\to_text\audio` |
| 動画の生成データ保存先 | `<data>\to_text\video` |
| 画像の生成データ保存先 | `<data>\to_text\image` |

ここでの `<data>` は Timeline のデータ保存先です。

例:

```text
C:\apps\Timeline\data
```

## 実装上の注意

ユーザーから見える設計として、以下を守ります。

- 設定の保存責任を 1 箇所にまとめる
- 基本設定と詳細カスタマイズの値を、画面内で一時的に保持する
- モードを切り替えても未適用の変更を失わない
- 個別設定がある場合は、基本設定側に簡潔な注意を出す
- 個別設定を一括で上書きする場合は、必ず確認を挟む
- 未インストール製品の設定は出さない
- 製品の再起動が必要な場合は、適用前に明示する
- 適用中は進行状況を表示する

## 優先度

### 高

- 「通常モード / プロモード」を「基本設定 / 詳細カスタマイズ」に変更する
- 製品ごとの保存ボタンをなくす
- 設定画面全体で `確認` → `適用する` に統一する
- 基本設定と詳細カスタマイズの一時状態を維持する
- Hugging Face トークンと AI 処理方法に、個別設定ありの表示を追加する
- `この設定をすべての製品に適用する` を共通操作として追加する
- 未保存状態で画面遷移しようとしたら警告する

### 中

- トークンとディレクトリの即時検証を追加する
- 適用時に再起動が必要な製品を表示する
- 適用中の進行状況を表示する
- インストール時に Timeline 側の基本設定からサブ製品設定を作る

### 後続

- サブ製品の `timeline-product.json` を使い、設定可能項目を推測せずに表示する
- 設定変更後の起動完了確認を製品ごとに安定化する
- 設定変更履歴を操作ログとして残す
