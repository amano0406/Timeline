Timeline 未来製品ロードマップ

Timeline を「個別の変換ツール群」ではなく、人生・作業・会話・ファイル・Web行動を時間軸で統合する製品として育てるための検討資料。 現在対応している Audio / Windows Codex / ChatGPT / Image を土台に、次に増やすべきサブ製品候補を整理する。

作成日: 2026-05-04 / 状態: 構想メモ

判断軸

時間軸価値

いつ何が起きたかを並べたとき、生活・仕事・意思決定の理解につながるか。

取得しやすさ

CLI、公式API、エクスポート、ローカルファイルとして安定的に取得できるか。

横断分析への寄与

Audio、ChatGPT、Codex、Image など他データと重ねたときに意味が増えるか。

安全性と運用性

パスワード保持、規約違反、過剰な個人情報収集、壊れやすい自動操作を避けられるか。

優先製品ランキング

順位 製品候補 優先度 役割 最初に扱うデータ
1 TimelineForFiles 最優先 PC内のファイル存在、作成日時、更新日時、パス、拡張子を拾う基盤製品。中身解析前の索引として重要。 PDF、CSV、TXT、SVG、Office、ZIP、任意ファイルのメタデータ。
2 TimelineForBrowser 最優先 Web閲覧、検索、ページタイトル、URL、滞在、Web行動を時間軸化する。Webサービス横断の土台。 Chrome / Edge 履歴、タイトル、URL、時刻、必要に応じてページ抜粋。
3 TimelineForGoogle 最優先 Googleアカウント由来の生活ログを扱う。OAuthやエクスポートを前提にし、パスワードは保持しない。 Gmail、Calendar、Drive、Photos、Google Takeout。
4 TimelineForDocuments 高 文書ファイルの中身を読み取り、文書イベントとして扱う。契約書、請求書、メモ、資料を時間軸へ載せる。 PDF、Word、Excel、PowerPoint、Markdown、HTML、プレーンテキスト。
5 TimelineForVideo 高 動画、画面録画、防犯カメラ録画、スマホ動画を扱う。Audio / Image と統合しやすい。 MP4、MOV、WebM、MKV、AVI、動画からの音声・フレーム・シーン変化。
6 TimelineForMessages 中高 人との会話ログを扱う。意思決定、関係性、作業依頼、生活イベントを時系列で見られる。 LINE、Discord、Slack、Teams、X DM、Instagram DM、各種エクスポート。
7 TimelineForCommerce 中高 購入・支払い・領収書を扱う。何をいつ買ったかは生活ログとして強い。 Amazon、楽天、Steam、領収書メール、CSV、注文履歴エクスポート。
8 TimelineForEmail 中 Google以外も含むメール全般を扱う。購入、契約、予約、予定、通知の入口になる。 Outlook、eml、mbox、IMAPエクスポート、メール本文・添付。
9 TimelineForCalendar 中 予定・会議・締切・イベントを扱う。Google専用を超える場合に独立させる。 Google Calendar、Outlook Calendar、ICS。
10 TimelineForCamera 中 室内・屋外カメラ、定点画像、録画を扱う。Videoに近いが、定期取得や動体検知があるなら独立価値がある。 監視カメラ録画、定点画像、動体検知イベント、カメラ別メタデータ。
11 TimelineForActivity 慎重 PC操作ログ、アプリ起動、ウィンドウタイトル、クリップボードなどを扱う。価値は高いがプライバシー負荷も高い。 アプリ使用履歴、ウィンドウタイトル、操作時間、クリップボード履歴。
12 TimelineForStructuredData 後続 構造化データを汎用的に取り込む。意味づけは難しいが、後から効いてくる基盤。 CSV、JSON、SQLite、ログファイル、家計簿、センサー値。
13 TimelineForLocation 後続 位置情報と移動を扱う。人生ログとして強いが、プライバシーが重い。 GPS、Google Maps Timeline、写真位置情報、移動履歴。
14 TimelineForArchives 補助 ZIPやバックアップを展開・分類し、他製品に渡す入口。単体製品より振り分け役。 ZIP、7z、tar、各種サービスエクスポート。
15 TimelineForWebAutomation 研究枠 APIやエクスポートがないWebサービスを、ログイン済みブラウザからAI/自動操作で読む。壊れやすく、最後の手段。 サービス個別画面、購入履歴ページ、チャットページ、管理画面。

Webアカウント系の安全原則

Timeline 本体やサブ製品に ID / パスワード一覧を保存する設計は避ける。 漏えい時の被害が大きく、MFA、規約、アカウント停止、監査性の面でもリスクが高い。

採用する認証方式は、OAuth、OS資格情報ストア、既存パスワードマネージャー連携、ログイン済みブラウザセッション、手動エクスポート取り込みを優先する。

最初の実装順

  1. TimelineForFiles を作り、PC内ファイルの存在と更新履歴を時間軸化する。
  2. TimelineForBrowser で閲覧履歴とWeb行動の入口を作る。
  3. TimelineForGoogle で Gmail / Calendar / Drive / Photos / Takeout を扱う。
  4. TimelineForDocuments で PDF / Office / テキスト類を文書イベント化する。
  5. TimelineForVideo で動画・画面録画・カメラ録画を扱う。
  6. TimelineForMessages と TimelineForCommerce を追加し、人とのやり取りと購入履歴を重ねる。

共通データ形の方向性

製品ごとに形式は異なってよいが、Timeline 側では最低限、発生時刻、ソース、種別、タイトル、本文または要約、元データ参照を揃える。 

{
  "occurredAt": "2026-05-04T10:30:00+09:00",
  "sourceProduct": "TimelineForBrowser",
  "sourceKind": "browser",
  "actionType": "view",
  "title": "検索結果",
  "body": "必要に応じて抽出テキストや要約",
  "sourceRef": {
    "url": "https://example.com",
    "localPath": null,
    "account": "personal-google"
  },
  "tags": ["web", "research"]
}

拡張子と製品の考え方

拡張子は製品分割の絶対基準ではなく、入口のヒントとして扱う。 例として GIF は Image と Video の境界にあるため、拡張子だけで決めず、静止画として扱うか、時間変化を持つ動画として扱うかで振り分ける。

基本方針は extension -> content kind -> product。 まず TimelineForFiles が全体を見つけ、必要に応じて Documents / Image / Video / StructuredData へ渡す。
