Timeline 設定導線 統合設計

分散していた「基本設定」「製品管理」「各サブ製品設定」を、ユーザーが迷わず扱える ひとつの設定ハブへ整理するための設計と実装メモ。

作成日: 2026-05-07 / 更新日: 2026-05-08 / 対象: Timeline Web UI / 状態: 設定モーダル統合実装済み

結論

現在の主案は、利用中の画面から 設定モーダル を開き、 モーダル内で「通常モード」と「プロモード」を切り替える形にする。 直接URL用の設定ページは残してよいが、通常の利用導線はモーダルへ集約する。

理由は、設定が頻繁に触る画面ではなく、画面遷移より「今いる作業を失わない」ことの価値が高いため。 長くなりすぎる項目はプロモードや折りたたみへ逃がし、通常モードではユーザーに必要な項目だけを見せる。

統合前の問題

設定入口が多い

サイドバーに本体設定、製品管理、各製品配下の設定が並び、 ユーザーが「今どこを触るべきか」を判断しなければならない。

配置用語が伝わりにくい

管理用の配置と開発用の配置が別々に見えると、利用者はどちらを触ればよいか判断できない。 Timeline から見れば「その製品をどこから使うか」だけが重要。

製品設定と配置管理が分断されている

製品一覧で状態は見えるが、その製品の入力ディレクトリや出力ディレクトリは別ページにある。 製品カードから自然に設定へ入れる方が認知負荷が低い。

普段触らない設定が常時見えている

設定は毎日使う主機能ではないため、通常導線からは控えめにし、問題がある時だけ明確に案内する方がよい。

設計原則

  1. サイドバーは日常操作を優先する。設定系リンクは左下に集約する。
  2. ユーザー概念ではない用語を出さない。製品配置は 管理配置 に統一する。
  3. 配置と製品設定は同じ製品カード内で見られるようにする。
  4. 画面は1か所に集約するが、保存はセクション単位に分ける。
  5. 保存後に再起動が必要な場合は、その場で状態を出す。
  6. 設定が不足している時は、各一覧ページから該当設定へ直接誘導する。

管理配置の扱い

UI上は製品配置を 管理配置 として扱う。開発中であっても、Timeline から見れば 「その製品をどこから使うか」という単一の情報で十分。

旧形式の設定が残っている場合は、読み取り時だけ移行互換として扱う。 保存する情報は製品ごとの単一パスへ寄せる。

保存と状態表示

  1. 設定ハブ全体に巨大な「すべて保存」は置かない。
  2. Timeline 本体、各製品ごとに 保存 を置く。
  3. 保存中は該当カードだけをロックする。他カードの閲覧は止めない。
  4. 保存成功時はカード内に 保存しました を表示する。
  5. CLI失敗時はそのカードにエラーを表示し、操作ログへ operation id を残す。
  6. 再起動が必要な変更は、製品行に 再起動が必要 または 再起動中 を表示する。

運用上の注意

サブ製品の設定保存は、引き続き各サブ製品の cli.ps1 経由で行う。 Timeline 側からサブ製品 Docker を直接操作しない。

設定ハブの統合は UI の導線整理であり、各製品の責務を Timeline に吸収するものではない。 Timeline は保存操作を橋渡しし、状態とログを見せる。

初期統合で実装した範囲

  1. /timeline/settings を設定ハブとして整理する。
  2. Timeline 本体設定を設定ハブへ移す。
  3. 製品管理を設定ハブへ移す。
  4. UI上の製品配置を 管理配置 に統一する。
  5. 各サブ製品設定をカードまたは折りたたみとして設定ハブへ移す。
  6. サイドバーから設定入口の重複を外す。
  7. 左下に 設定 と 操作ログ を置く。
  8. 不足設定のアラートから該当セクションへ遷移できるようにする。
  9. 旧設定ページURLを設定ハブで受け、旧画面は表示しない。
  10. Timeline 本体と管理配置の保存ボタンは製品別設定より前に置き、保存対象を明確にする。
  11. 製品別設定へのリンクは product クエリで対象製品を指定する。

今後の別作業

  • 製品インストール、更新、アンインストールの安全な確認フローを設計する。
  • GitHub source archive ZIP、Git clone、配信サーバーなどの入手方式を決める。
  • 製品操作を実行した場合の操作ログ、失敗時ログ、復旧導線を設計する。

受け入れ条件

  • ユーザーがサイドバー上で設定リンクを複数探さなくてよい。
  • 設定に関する入口は左下の 設定 にまとまっている。
  • 管理者・開発者向けの配置用語が画面に出ない。
  • 製品ごとの管理配置と製品設定が同じカード内で確認できる。
  • 保存に失敗した場合、該当製品カードにエラーが出て操作ログにも残る。
  • 再起動が必要な設定変更は、保存直後にユーザーへ伝わる。
  • スマホでは設定カテゴリが縦に並び、横スクロール前提にならない。

決定事項

  • 製品をまとめる親ディレクトリ概念は削除し、製品ごとの管理配置だけを扱う。
  • 旧製品管理ページは削除し、設定モーダルへ統合する。
  • 旧URLに直接入った場合は、旧画面を復活させず設定画面へ誘導する。
  • 製品の起動と再起動はダッシュボードから外す。
  • 製品インストール、アンインストール、更新は設定画面から一旦外し、別の製品導入設計として扱う。
  • 製品別設定は設定モーダル内のプロモードで表示し、サイドバー上の設定リンクは重複させない。
  • 製品別設定は各製品の保存ボタンで保存し、Timeline 本体設定の保存ボタンとは分ける。
  • ダッシュボードや製品カードからの設定リンクは、対象製品の設定タブへ直接遷移する。
