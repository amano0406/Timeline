スキャンと時間軸整理 UI 試作

スキャン、変換、言語化、時間軸反映をユーザーに何度も押させないための画面案。 ここでは本実装ではなく、レビュー用のABC案として見る。

作成日: 2026-05-08 / 対象: Timeline Web UI / 状態: 試作レビュー用

前提

ユーザーが本当に知りたいのは、各サブ製品のCLI名や処理名ではなく、 「素材が取り込まれているか」「時間軸に使える状態か」「未処理や失敗が残っていないか」。 そのため、ボタンは少なくし、基本は自動で最新化する画面として考える。

案A: 取り込み状況ダッシュボード型

サブ製品別の素材取得状態を中心に見る。最も現在の一覧ページ群から移行しやすい。

この案の特徴

一方で、時間軸そのものの価値はまだ少し後ろに下がる。

案B: 時間軸を整える中心型

スキャンを内部処理として扱い、ユーザーには「時間軸を使える状態に整えている」と見せる。

この案の特徴

Timeline 本体の価値が一番見えやすい。スキャン、変換、言語化を「時間軸を整える」に吸収できる。

ただし、サブ製品別に正しく取れているかを詳細確認する入口を別途きれいに用意する必要がある。

案C: 自動処理センター型

ただし、ユーザーに処理名を見せすぎるため、主画面にすると認知負荷が上がる可能性がある。

比較

案A

サブ製品の一覧確認を自然に統合できる。現行UIからの移行が簡単。

案B

Timeline の主価値が出る。最終形として一番強いが、詳細確認導線の設計が必要。

案C

採用案。ユーザーが何度も実行する画面ではなく、Timeline が自動で整えている状態を確認する画面として使う。
