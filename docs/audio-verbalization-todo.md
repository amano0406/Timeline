## 2026-05-10 少数検証結果

- `audio-verbalization-v3` では、根拠が薄い候補や動画側の長い幻覚候補が通ってしまったため、製品品質には届かないと判断した。
- `audio-verbalization-v4` で、要約、背景説明、知識補完、話題拡張を禁止し、返却候補のローカル検証を追加した。
- `audio-verbalization-v5` で、短い `phoneTextHint` だけから作られた候補をさらに安全側で落とすようにした。
- 2026-05-10 の少数検証ジョブ `audio-verbalization-bulk-20260510-112756-9285ed43` は、音声1件・動画1件、33区間を処理し、読める候補 0 件、未解決 33 件で完了した。
- 現時点では、誤った言語化候補を増やさない安全側の制御は入ったが、実用的な日本語化品質はまだ出ていない。
- 全件処理へ戻すには、周辺ヒントの選び方、音声/動画の `phoneTextHint` 生成、Ollama への投入単位を再設計する必要がある。

## 全件処理へ戻すための品質ゲート案

この条件を満たすまでは、スキャン時の一括言語化対象は音声1件・動画1件の検証モードに留める。

- 音声と動画を別々に少なくとも5件ずつ検証し、10分前後、短時間、長時間の素材が混ざっていること。
- 返却結果が要約ではなく、発話単位の文字化・翻訳候補になっていること。
- `ja-JP` の場合、ローマ字だけ、カタカナだけ、英語だけの候補へ偏らず、自然な日本語候補として返ること。
- 根拠が薄い区間では、無理に候補を作らず未解決として残ること。
- ファイル名、前後1日のTimelineヒント、直前チャンク結果を使った場合でも、周辺情報を本文へ混ぜて要約しないこと。
- 音声と動画の両方で、実際に読める候補が継続して出ること。候補0件のまま安全側に倒れる状態は、全件処理へ戻す根拠にはしない。
- 少数検証で問題がなければ、次は10件、50件、全件の順に段階拡大する。段階拡大中に要約化や幻覚候補が増えた場合は、直前段階へ戻す。
