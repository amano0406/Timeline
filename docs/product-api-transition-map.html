API-only integration

Timeline Product API Map

Timeline talks to sub-products through each product's local HTTP API. Product manifests keep only runtime launchers such as start, stop, and PC service setup. Normal data operations are API requests.

Product API access is intentionally gated by /health. If a product is not running, Timeline reports that state instead of starting the product implicitly.

Timeline Local API Routes

Timeline route Sub-product route Products Purpose
POST /products/{id}/refresh POST /items/refresh Audio, Image, Video, ChatGPT, WindowsCodex, PC Collect or rebuild product-side item data.
GET /products/{id}/items POST /items/list ChatGPT, WindowsCodex, PC where proxied; file readers for Audio, Image, Video Return paged item rows for Timeline screens and store rebuild.
POST /products/{id}/items/download POST /items/download Audio, Image, Video, ChatGPT, WindowsCodex, PC Create a ZIP handoff archive in a Timeline-managed work directory.
POST /products/{id}/items/delete-generated POST /items/remove Audio, Image, ChatGPT, WindowsCodex Remove generated product artifacts for selected items.
POST /products/{id}/settings Product settings file contract All products Apply Timeline-managed settings and then let the product API expose the new state.

Do not add an automatic start side effect to product API calls. A product that is not running should be reported as stopped so the user can start it explicitly from the product management screen.
