音声フォントークン言語化 実装メモ

TimelineForAudio が生成したフォントークンを、Timeline 本体が周辺の時間軸データと LLM を使って日本語などの読める候補へ変換するための実装方針。 言語化結果は確定文字起こしではなく、後段分析で使う有力候補として扱う。

作成日: 2026-05-04 / 対象: Timeline 本体 / 初期LLM: Ollama + qwen3.5:9b

責務

TimelineForAudio は音声から話者区間、時刻、フォントークンを作る。Timeline 本体は、そのフォントークンに前後の時間軸ヒントを加えて、読める言語の候補を生成する。 

TimelineForAudio
  audio -> speaker turns -> phone tokens

Timeline
  phone tokens + nearby timeline context + LLM
  -> verbalized text candidates

処理単位

単位 採用判断 理由
発話1件 不採用 前後文脈が足りず、LLM呼び出し回数も増えすぎる。
5〜10分チャンク 採用 文脈、処理時間、失敗時再実行のバランスがよい。
音声ファイル全体 短い音声のみ 長い音声ではコンテキスト過多、失敗時のやり直しが重い。
複数音声まとめ 初期は不採用 異なる文脈が混ざり、誤解釈が増える。

初期実装では、1チャンクを最大10分、最大80ターン、入力見積もり上限を超えたら分割する。

逐次処理の原則

チャンクは並列処理せず、音声ファイル内の時系列順に1つずつ処理する。 完了したチャンクの言語化結果と要約は、次チャンクのヒントとして渡す。 

chunk-0001 -> result + summary
chunk-0002 uses chunk-0001 summary
chunk-0003 uses chunk-0001..0002 rolling summary
...

未確認の言語化結果を使う場合は、強い根拠としてではなく「弱いヒント」として扱う。誤解釈の連鎖を避けるため、LLM入力にもその旨を明記する。

ジョブ構成

AudioVerbalizationJob

音声ファイル1件、または選択された複数ファイルの言語化ジョブ。全体の進捗と状態を持つ。

AudioVerbalizationChunk

5〜10分単位の実行単位。LLM入力、LLM結果、処理時間、失敗情報を持つ。

{
  "jobId": "audio-verbalization-20260504-...",
  "kind": "audio_verbalization",
  "state": "running",
  "model": "qwen3.5:9b",
  "language": "ja-JP",
  "targetAudioItemIds": ["..."],
  "totalChunks": 12,
  "completedChunks": 4,
  "totalTurns": 428,
  "completedTurns": 151,
  "currentChunkId": "chunk-0005",
  "estimatedRemainingSeconds": 900
}

保存場所

C:\TimelineData\Timeline\store\
  audio-verbalizations\
    <audio-item-id>\
      verbalization-run.json
      audio-verbalization.json
      context\
        chunk-0001.context.json
        chunk-0002.context.json
      results\
        chunk-0001.result.json
        chunk-0002.result.json

TimelineForAudio の成果物は上書きしない。言語化は Timeline 本体が持つ派生データとして保存する。

未処理判定

単に結果ファイルがあるかではなく、モデル、プロンプト、周辺情報収集方針、元音声タイムラインのハッシュを含む signature で判定する。 

verbalizationSignature =
  audioTimelineHash
  contextPolicyVersion
  promptVersion
  modelName
  modelOptions
  language

signature が変わった場合は再言語化対象にできる。ただし初期UIでは自動再処理ではなく、ユーザー操作で実行する。

LLM入力

LLMへは、対象チャンクの発話ターン、ファイル情報、前後ヒント、直前チャンクの言語化要約を渡す。 

{
  "language": "ja-JP",
  "audio": {
    "fileName": "meeting-2026-05-04.m4a",
    "recordedAt": "2026-05-04T10:00:00+09:00"
  },
  "chunk": {
    "chunkId": "chunk-0002",
    "startSec": 600,
    "endSec": 1200,
    "turns": [
      {
        "turnId": "turn-0041",
        "speaker": "SPEAKER_00",
        "startSec": 612.4,
        "endSec": 618.2,
        "phoneTokens": "..."
      }
    ]
  },
  "previousVerbalizedContext": {
    "summary": "設定変更と再スキャンについて話している可能性が高い。",
    "confirmed": false
  },
  "nearbyTimelineHints": [
    {
      "product": "windows-codex",
      "occurredAt": "2026-05-04T10:08:00+09:00",
      "title": "TimelineForAudio settings discussion"
    }
  ]
}

LLM出力

返却は自由文ではなく、ターンIDごとのJSONに固定する。根拠、信頼度、不確実語を残す。 

{
  "chunkId": "chunk-0002",
  "language": "ja-JP",
  "chunkSummary": "入力ディレクトリと再スキャンについて話している可能性が高い。",
  "turns": [
    {
      "turnId": "turn-0041",
      "text": "入力ディレクトリを変更したら再スキャンしてください",
      "confidence": 0.63,
      "status": "candidate",
      "uncertainTerms": ["入力ディレクトリ", "再スキャン"],
      "basis": ["phone_tokens", "previous_chunk_summary", "nearby_codex_thread"]
    }
  ]
}

通常操作

LLM処理中でも一覧閲覧、音声再生、他ページ操作は続けられるようにする。

Ollama起動構成

Ollama は Timeline 本体の `docker-compose.yml` に含める。`start.ps1` で Web、worker、Ollama を同時に起動し、初回のみ既定モデルを取得する。 補助サーバーは Windows 側から `http://127.0.0.1:11434` に接続する。 

services:
  ollama:
    image: ollama/ollama:latest
    ports:
      - "127.0.0.1:11434:11434"
    volumes:
      - ollama:/root/.ollama
    gpus: all

MVP実装順

  1. Timeline 設定に Ollama / モデル / 言語化設定を追加する。
  2. 音声詳細APIに既存の言語化結果を返すフィールドを追加する。
  3. 音声1件を5〜10分チャンクへ分割する関数を追加する。
  4. チャンクごとの context JSON を作る。
  5. Ollama APIを呼ぶ LLM クライアントを追加する。
  6. 結果JSONを検証して、Timeline storeへ保存する。
  7. 音声詳細画面に進捗と結果表示を追加する。
  8. 失敗チャンクのみ再試行できるようにする。
