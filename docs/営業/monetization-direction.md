# Timeline 売り方の方向性

作成日: 2026-06-04

## 目的

Timeline をこのまま個人用ツールとして置くのか、商品として成立させるのかを判断するための営業・マーケティング方針をまとめる。

ここでは実装方針ではなく、次の判断を扱う。

- 誰に向けるか
- 何として見せるか
- どの売り方なら続けられるか
- 何を避けるか
- どの状態なら商品化を続けるか

## 現時点の結論

Timeline は、そのまま「ローカルのデータを時系列で集めるアプリ」として出すと弱い。

商品化するなら、次の方向に寄せる。

> AI を使って仕事をする人のために、ローカルの作業・会話・画面・AI利用履歴を時系列化し、あとから AI に渡せる作業文脈を作る製品。

中心価値は「記録」ではなく「文脈化」である。

## 強い訴求

### 作業記憶

昨日の作業、過去の判断、会話、画面、ファイル、AIとのやりとりを後から復元できる。

### AI 文脈化

音声、画面、ChatGPT、Codex、ファイルなどを、AI に渡しやすい文脈として束ねる。

### ローカル証跡

データを外部サービスに預けるのではなく、手元のPCに残し、出所をたどれる形で扱う。

## 弱い訴求

以下の見せ方は避ける。

- 何でも記録するライフログ
- 会議メモ専用ツール
- 魔法のAI秘書
- 大企業向け監査システム
- 汎用ナレッジ管理ツール

これらは競合が強いか、期待値が大きすぎるか、初期開発・運用コストが高すぎる。

## 最初に狙うユーザー

優先する対象:

- AI を日常的に使う開発者
- ChatGPT / Codex / ローカルファイル / 録音 / 画面録画をまたいで作業する人
- 個人事業主、コンサル、制作職
- あとから作業経緯や判断理由を復元したい人

優先しない対象:

- 普通の会議メモ利用者
- 一般的なライフログ利用者
- 企業の法務・監査・医療用途
- 手厚い導入支援を期待するユーザー

## 売り方の前提

ユーザー本人の性格・運用負荷を考えると、次の売り方が合う。

- 対面営業をしない
- 通話営業をしない
- 現地対応をしない
- 重いコミュニティ運営をしない
- できるだけ Codex 上で文章、ページ、投稿、改善を作る
- サポートはテキスト非同期を基本にする

そのため、最初から大きな SaaS や企業営業を狙わない。

## 推奨する初期商品

最初は完成品として売るのではなく、有料ベータまたは Founder Access として売る。

仮の商品名:

```text
Timeline Founder Access
```

説明の方向:

```text
AIを使って仕事をする人のための、ローカル作業記憶ツール。
音声、画面、ChatGPT、Codex、ファイルを時系列でまとめ、
あとからAIに渡せる作業文脈を作ります。
```

## 価格仮説

初期検証では、価格を出す。

候補:

- 4,980円: 早期アクセス
- 9,800円: Founder Access
- 14,800円: 更新アクセス込みの個人ライセンス
- 29,800円: 非同期セットアップ支援付き

ただし、サポート負荷を増やしすぎないため、最初は 9,800円前後が扱いやすい。

## 提供物

初期商品に含めるもの:

- 現在版の利用権
- セットアップ手順
- 更新版へのアクセス
- テキスト非同期での問い合わせ窓口

含めないもの:

- 通話サポート
- 個別カスタム開発
- 業務導入支援
- データ移行代行
- 企業向け保証

## 検証方法

30日程度で小さく検証する。

成功条件:

- 10人が説明ページを見る
- 3人が「使いたい」と言う
- 1人が購入する

この条件を満たさない場合、商品化を急がず、個人用ツールとして維持してよい。

1人でも購入した場合は、自分以外にも痛みを持つ人がいる可能性があるため、商品化検証を続ける。

## 販売導線

最初の導線:

1. 説明ページを作る
2. スクリーンショットを3枚用意する
3. デモシナリオを3つに絞る
4. Gumroad などで早期アクセス商品を置く
5. X / Zenn / Qiita / GitHub README などに投稿する
6. 購入、問い合わせ、反応だけを見る

外部サービスへの公開・販売設定は、ユーザー確認後に行う。

## デモシナリオ

最初に見せるデモは、次の3つに絞る。

### 昨日の作業を復元する

Codex の作業、ファイル変更、ChatGPT の会話、PC上の痕跡を時間軸で見る。

### 音声を周辺情報つきで補正する

音声単体では不完全な文字化を、同時刻のファイル、画面、AI会話、作業ログを使って補正する方向を示す。

### AI に渡す文脈パックを作る

特定期間の作業記録を、AI が読みやすい入力データとしてまとめる。

## Docker について

商品化を考えると、Docker 必須は導入障壁になる。

ただし、初期検証では Docker が残っていてもよい。

段階的な考え方:

- 初期検証: Docker ありでも許容
- 有料ベータ: Timeline 本体は Docker なしを目指す
- 一般販売: Docker を意識させない起動方法を目指す

完全撤去よりも、まずは実行方式を抽象化し、Docker 実行と native 実行を並存させる方が安全。

## 判断基準

商品化を続ける条件:

- 自分以外が実データで使う
- 同じ用途への反応が複数ある
- 有料でも使いたい人が出る
- 導入の壁を越える価値が確認できる

商品化を止める条件:

- 反応が「便利そう」だけで止まる
- 誰も自分のデータを入れない
- 価格を出すと反応が消える
- サポート負荷だけが増える
